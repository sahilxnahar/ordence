# Deployment — the whole thing, in order

Written to be followed literally. Every command is copy-paste. Nothing
here assumes you know what a build adapter is.

---

## Part 0 — Get this release onto your machine

```bash
cd ~/Documents/GitHub/ordence
tar -xzf ordence-deploy-final.tgz
npm install
```

`npm install` matters this time — this release added two packages
(`tailwind-merge`, `@axe-core/playwright`). Skipping it makes the build
fail with "module not found".

---

## Part 1 — Delete these three things

You said you have not deleted anything yet. Here is the complete list.
Nothing else in the repo is dead.

**1. `_to_delete/`** — a scratch folder I created because the cloud
bridge is not allowed to delete files on your disk, only move them. It
contains old archives and stale git lock files. Delete the whole folder.

```bash
rm -rf ~/Documents/GitHub/ordence/_to_delete
```

**2. `.DS_Store`** — macOS Finder junk. Already gitignored.

```bash
rm -f ~/Documents/GitHub/ordence/.DS_Store
```

**3. `.open-next/` and `.wrangler/` — from git, not from disk.** These
are build output. They are regenerated by every build, they are hundreds
of megabytes, and until this release they were **not** in `.gitignore`,
so git may already be tracking them. This command removes them from git
while leaving them on disk:

```bash
cd ~/Documents/GitHub/ordence
git rm -r --cached .open-next .wrangler 2>/dev/null; echo done
```

If that prints errors about paths not matching, git was not tracking them
and there is nothing to do.

> **Looks unused but is not:** `src/app/_parked/`. The underscore makes it
> a private folder that Next.js does not turn into routes. That is how the
> admin console stays parked until you say it ships. Leave it.

## Part 2 — Check it locally before you push

Two commands, two terminals. **This is the step that matters most.**

Terminal 1:

```bash
cd ~/Documents/GitHub/ordence
npx opennextjs-cloudflare build
npx wrangler dev --port 8787 --local
```

Then open `http://localhost:8787`.

**Do not check with `npm run dev` or `npm run build` and call it done.**
Those run Next's own server, which is a *different runtime* from the one
Cloudflare uses. This release fixes a bug that was invisible under
`npm run build` and threw an error on every single page in the deployed
bundle. If it does not run through `opennextjs-cloudflare` and `wrangler`,
it has not been tested.

Optional, same terminal setup, checks nothing regressed:

```bash
npx vitest run                                   # 40 unit tests
PW_CHROME=<path-to-chromium> PORT=8787 npm run audit:a11y     # accessibility
PW_CHROME=<path-to-chromium> PORT=8787 npm run audit:layout   # alignment
```

## Part 3 — Push

Commit and push in GitHub Desktop as normal. Cloudflare picks it up.

If GitHub Desktop complains about a lock file:

```bash
rm -f ~/Documents/GitHub/ordence/.git/index.lock
```

That happens because the cloud sandbox I work in cannot delete files on
your disk, so a lock git created can get left behind. Harmless, and the
command above clears it.

## Part 4 — The Cloudflare settings

Set once, in the Cloudflare dashboard → **Workers & Pages** → your
project → **Settings** → **Build**.

| Field | Value |
|---|---|
| Build command | `npx opennextjs-cloudflare build` |
| Deploy command | `npx wrangler deploy` |
| Build output directory | *(leave empty)* |
| Root directory | *(leave empty)* |
| Node version | `22` |

**The build command is the single most common thing to get wrong.** It
must be `npx opennextjs-cloudflare build`. If it says `npm run build`, the
deploy fails with:

```
Could not find compiled Open Next config
```

That error has bitten this project twice. It always means the same thing.

### KV namespaces

Two bindings, both already declared in `wrangler.jsonc`. If you ever
recreate them, paste the IDs **without** the angle brackets — pasting
`<abc123>` instead of `abc123` is a real failure mode from earlier.

| Binding | Purpose |
|---|---|
| `TENANT_KV` | Tenant registry, signup requests, captured leads |
| `NEXT_INC_CACHE_KV` | Next.js incremental cache (ISR) |

### DNS

One wildcard record does all tenant subdomains. This is why provisioning a
new customer is a single KV write and never a DNS API call.

| Type | Name | Target | Proxy |
|---|---|---|---|
| CNAME | `*` | your Workers route | Proxied (orange cloud) |
| CNAME | `@` | your Workers route | Proxied (orange cloud) |

### Secrets

Not in any file, never committed. Set from your machine:

```bash
npx wrangler secret put RESEND_API_KEY
```

## Part 5 — The two things still outstanding on your side

Neither is code. Both block a feature until done.

**Resend.** Verify `send.ordence.com` in the Resend dashboard, then run
the `wrangler secret put` command above. Until then, email fails soft —
signup still works, the notification just never arrives.

**Cloudflare Access.** Parts B–D in `DEPLOYMENT-ACCESS.md` must be
finished before `admin.ordence.com` is bound to anything. The admin
console has no application-level login; Access at the edge *is* its
authentication. Binding the hostname first would publish it unprotected.

## Part 6 — If something breaks

| Symptom | Cause | Fix |
|---|---|---|
| `Could not find compiled Open Next config` | Build command is `npm run build` | Change it to `npx opennextjs-cloudflare build` |
| `Node.js middleware is not currently supported` | `src/middleware.ts` was renamed to `proxy.ts` | Rename it back. Next 16 prefers `proxy.ts`, but that compiles to the Node runtime, which the Cloudflare adapter cannot execute. `middleware.ts` compiles to edge. |
| `module not found` after a pull | Dependencies changed | `npm install` |
| Tenant subdomain 404s | Tenant missing or plan lapsed | Check `TENANT_KV`; expired plans self-suspend on read |
| e2e tests fail on "already exists" | Leftover local KV state | `rm -rf .wrangler/state` between runs |

## What runs where, in one paragraph

`ordence.com` is the marketing site. `admin.ordence.com` rewrites to the
admin console and is gated by Cloudflare Access at the edge, not by app
code. `app.ordence.com` returns 404 from this codebase on purpose —
your separate CRM application owns that hostname. Anything else under
`*.ordence.com` is treated as a tenant slug, looked up in KV, and served
as that customer's branded workspace. All of it is one Worker, one
wildcard DNS record, and a single edge router in `src/middleware.ts` —
which is the file to read first if routing ever behaves strangely.
